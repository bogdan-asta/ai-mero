# EventAI

Веб-платформа, которая помогает пройти путь от идеи мероприятия до плана подготовки и документов.

## Текущая версия

Этапы 0–7: адаптивный лендинг, темы оформления, Supabase Auth, защищённые маршруты и RLS, CRUD мероприятий, чат EventAI и планирование, задачи и реквизит, площадки и бронирования, шаблоны документов с экспортом в DOCX, доска идей, команда и уведомления.

## Требования

- Node.js 20.9 или новее
- npm 10 или новее
- Проект Supabase для последующих этапов

## Запуск локально

```powershell
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Для проверки кода:

```powershell
npm run lint
npm run build
```

## Настройка Supabase

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. Откройте **Project Settings → API**.
3. Скопируйте Project URL и ключ `anon` / publishable.
4. Создайте локальный файл окружения:

   ```powershell
   Copy-Item .env.example .env.local
   ```

5. Заполните в `.env.local` значения `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
6. Откройте **SQL Editor** в Supabase и последовательно выполните миграции из `supabase/migrations/` по возрастанию имени:
   - `20261027000000_profiles.sql`
   - `20261027000001_events.sql`
   - `20261027000002_ai_assistant.sql`
   - `20261027000003_tasks_equipment.sql`
   - `20261027000004_venues_bookings.sql`
   - `20261027000005_documents.sql`
   - `20261027000006_team_ideas_notifications.sql`
7. В **Authentication → URL Configuration** укажите Site URL `http://localhost:3000` и добавьте Redirect URL `http://localhost:3000/auth/callback`.
8. Для входа через Google включите провайдер Google в **Authentication → Providers** и настройте OAuth client ID/secret у Google. Email/password и magic link доступны без настройки Google.

Не добавляйте секретный `service_role` ключ в переменные `NEXT_PUBLIC_*`, клиентский код или Git.

После настройки откройте `/sign-up`, зарегистрируйтесь, подтвердите email (если подтверждение включено в Supabase) и заполните онбординг. Для локального теста проверьте `/sign-in`, вход по magic link, выход и восстановление пароля.

## Настройка OpenRouter

Для чата и генерации плана нужен ключ в [OpenRouter](https://openrouter.ai/). Добавьте `OPENROUTER_API_KEY`, `OPENROUTER_CHAT_MODEL` и, при необходимости, `OPENROUTER_FALLBACK_MODEL` в локальный `.env.local` и переменные серверного окружения при деплое. Модели задаются идентификаторами OpenRouter. Ключ используется только серверными API-маршрутами и не нужен для просмотра сайта или работы с мероприятиями.

Откройте карточку мероприятия и выберите **Спросить ИИ**. История чата сохраняется отдельно для каждого пользователя и мероприятия. Кнопка **Составить план** создаёт черновик с целью, аудиторией, программой и рисками. Проверьте содержимое и нажмите **Проверил(а), применить к мероприятию**, чтобы сохранить его; участники могут создавать планы, но применять их может только организатор. Запросы к ИИ ограничены 15 обращениями в минуту на пользователя.

Во вкладках **Задачи** и **Реквизит** организатор может добавлять и удалять записи, задавать сроки и приоритеты, отмечать выполнение и обновлять статус оборудования. Участники мероприятия видят списки в режиме чтения. Доступ защищён RLS; участнику-организатору разрешается управление на уровне БД.

Каталог доступен по адресу `/venues`, а запрос на бронирование создаётся во вкладке **Площадка** мероприятия. При отправке база данных проверяет вместимость и пересечение с ожидающими или подтверждёнными бронированиями; площадка принимает или отклоняет заявку из каталога. Для настройки каталога администратор Supabase должен назначить аккаунту роль площадки из SQL Editor, например: `update public.profiles set role = 'venue_admin' where email = 'admin@example.com';`. Роль нельзя изменить из пользовательского интерфейса.

Во вкладке **Документы** доступны шаблоны приказа, приглашения, запроса площадке и краткой справки. Неизвестные реквизиты оставляются в квадратных скобках для заполнения организатором. Черновики сохраняются в базе мероприятия, редактируются организатором и выгружаются в DOCX; участники могут просматривать сохранённые документы.

Во вкладке **Идеи** участники добавляют предложения и голосуют; во вкладке **Команда** организатор приглашает зарегистрированных пользователей по email с ролью участника или организатора. Приглашённый принимает или отклоняет приглашение на странице **Уведомления**. Там же отображаются обновления бронирования; письма не отправляются, уведомления доступны внутри приложения.

## Структура

```text
src/
  app/                 страницы, layout, провайдеры темы
  components/ui/       компоненты shadcn/ui
  lib/supabase/        клиенты Supabase для браузера и сервера
  lib/utils.ts         общие утилиты UI
supabase/
  migrations/          SQL-миграции, включая профили и RLS
  seed.sql             тестовые данные (будут добавлены вместе с моделью данных)
.env.example           пример локальной конфигурации без секретов
DECISIONS.md            принятые технические решения
```

Маршруты авторизации: `/sign-in`, `/sign-up`, `/forgot-password`, `/auth/update-password`. Защищённые маршруты: `/onboarding`, `/dashboard` и `/events`. Владелец мероприятия может редактировать и удалять его; участники видят только мероприятия, в которые добавлены.
