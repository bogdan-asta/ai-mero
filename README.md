# EventAI

Веб-платформа для создания мероприятий и подготовки плана с помощью ИИ.

## Текущая версия

Текущий MVP: адаптивный лендинг, Supabase Auth, профили, мероприятия и AI-чат с генерацией плана. Дополнительные модули задач, реквизита, площадок, документов, команды, идей и уведомлений временно отключены. Их существующие таблицы и данные не удаляются; production-миграция закрывает доступ к ним через клиентское API.

## Требования

- Node.js 20.9 или новее
- npm 10 или новее
- Проект Supabase для последующих этапов

## Запуск локально

```powershell
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Для проверки кода:

```powershell
npm run lint
npm run build
```

## Настройка Supabase

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. Откройте **Project Settings → API**.
3. Скопируйте Project URL и ключ `anon` / publishable.
4. Создайте локальный файл окружения:

   ```powershell
   Copy-Item .env.example .env.local
   ```

5. Заполните в `.env.local` значения `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
6. Выберите вариант для базы:
   - **Новая пустая база:** откройте Supabase **SQL Editor**, скопируйте содержимое `supabase/mvp-schema.sql` и выполните один раз. Скрипт создаёт только профили, мероприятия и необходимые таблицы AI.
   - **Существующая база** с миграциями `20261027000000`–`20261027000006`: выполните только `supabase/migrations/20261027000007_mvp_core.sql`. Она переводит доступ на модель «владелец мероприятия» и не удаляет таблицы или записи.
7. В **Authentication → URL Configuration** укажите Site URL `http://localhost:3000` и добавьте Redirect URL `http://localhost:3000/auth/callback`.
8. Для входа через Google включите провайдер Google в **Authentication → Providers** и настройте OAuth client ID/secret у Google. Email/password и magic link доступны без настройки Google.
9. Для гостевого входа в локальной разработке включите anonymous sign-ins в настройках **Authentication → Sign In / Providers**. Кнопка гостевого входа отображается только при запуске `npm run dev`; каждый вход создаёт анонимного пользователя Supabase, поэтому этот режим не предназначен для production.

Не запускайте `mvp-schema.sql` поверх существующей базы, не редактируйте старые миграции и не запускайте их повторно. Разворачивайте обновлённый код и миграцию согласованно: существующие события после миграции доступны только создавшим их аккаунтам.

Не добавляйте секретный `service_role` ключ в переменные `NEXT_PUBLIC_*`, клиентский код или Git.

После настройки откройте `/sign-up`, зарегистрируйтесь, подтвердите email (если подтверждение включено в Supabase) и заполните онбординг. Для локального теста также можно открыть `/sign-in` и выбрать «Продолжить как гость»; для обычного входа проверьте magic link, выход и восстановление пароля.

## Настройка OpenRouter

Для чата и генерации плана нужен ключ в [OpenRouter](https://openrouter.ai/). Добавьте `OPENROUTER_API_KEY`, `OPENROUTER_CHAT_MODEL` и, при необходимости, `OPENROUTER_FALLBACK_MODEL` в локальный `.env.local` и переменные серверного окружения при деплое. Модели задаются идентификаторами OpenRouter. Ключ используется только серверными API-маршрутами и не нужен для просмотра сайта или работы с мероприятиями.

Откройте карточку мероприятия и выберите **Спросить ИИ**. История чата сохраняется отдельно для пользователя и мероприятия. Кнопка **Составить план** создаёт черновик с целью, аудиторией, программой и рисками. Проверьте содержимое и нажмите **Проверил(а), применить к мероприятию**, чтобы сохранить его. Запросы к ИИ ограничены 15 обращениями в минуту на пользователя.

Данные текущего MVP принадлежат только создавшему мероприятие аккаунту. Дополнительные разделы временно отключены. В существующей базе связанные таблицы сохраняются, но миграция закрывает к ним доступ через клиентское API; удалить сохранённые данные можно отдельной миграцией только после резервного копирования и подтверждения.

## Структура

```text
src/
  app/                 страницы, API-маршруты, layout, провайдеры темы
  components/          интерфейсные компоненты и сценарии событий
  components/ui/       компоненты shadcn/ui
  lib/supabase/        клиенты Supabase для браузера и сервера
  lib/utils.ts         общие утилиты UI
supabase/
  migrations/          последовательные SQL-миграции и RLS-политики
.env.example           пример локальной конфигурации без секретов
DECISIONS.md            принятые технические решения
```

Маршруты авторизации: `/sign-in`, `/sign-up`, `/forgot-password`, `/auth/update-password`. Защищённые маршруты: `/onboarding`, `/dashboard`, `/events`, `/venues` и `/notifications`. Доступ к данным мероприятий, команды, бронирований и документов дополнительно ограничен RLS.

## Развёртывание в production

1. Импортируйте репозиторий `bogdan-asta/ai-mero` в Vercel и подключите ветку `main`.
2. В настройках проекта Vercel добавьте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Для включения ИИ добавьте `OPENROUTER_API_KEY` и `OPENROUTER_CHAT_MODEL`; `OPENROUTER_FALLBACK_MODEL` — опционален. Не добавляйте `service_role` в окружение Next.js.
3. Для новой базы выполните `supabase/mvp-schema.sql`. Для существующей базы, где уже применялись миграции `20261027000000`–`20261027000006`, выполните только `supabase/migrations/20261027000007_mvp_core.sql`. Не запускайте `mvp-schema.sql` поверх существующей базы и не запускайте старые миграции повторно.
4. После первого deploy укажите домен Vercel в **Supabase → Authentication → URL Configuration** как Site URL и добавьте `https://<ваш-домен>/auth/callback` в Redirect URLs. Обновите OAuth callback URL провайдера Google, если он включён.
5. Для локального гостевого входа включите anonymous sign-ins в Supabase Auth. Кнопка доступна только при `npm run dev`; не включайте гостевой режим в production без отдельного решения по защите от злоупотреблений.
6. Проверьте production smoke flow MVP: вход, создание мероприятия, чат и план при настроенном OpenRouter. Задачи, документы, приглашения и бронирования пока отключены.

Внешние Supabase и OpenRouter credentials в репозитории не хранятся. Реальные интеграционные сценарии запускаются после настройки собственных проектов и секретов.
