# Решения по проекту

## Этап 0 — основа

- Используется актуальная стабильная версия Next.js с App Router, TypeScript и Tailwind CSS. Это соответствует требованию Next.js 14+ и даёт поддерживаемую основу для новых маршрутов.
- Интерфейс и системные сообщения приложения на русском языке; исходные тексты пока размещаются рядом с экранами, отдельная локализация будет выделена при появлении второго языка.
- Шаблон shadcn/ui и CSS-переменные темы подготовлены для светлого, тёмного и системного режимов.
- Доступ к Supabase разделён на клиентский и серверный модули. Переменные проверяются при создании клиента; приложение не подменяет отсутствующую конфигурацию фиктивными значениями.
- Ключ OpenRouter не используется в браузере и добавлен только как серверная переменная для будущего этапа с ИИ.
- Внешние подключения не требуют ключей для старта лендинга; реальные авторизация, БД и ИИ подключаются на соответствующих этапах.

## Этап 1 — авторизация и профили

- Подключены пароль, magic link и Google OAuth через Supabase Auth; обработчик callback обменивает одноразовый код на серверную сессию.
- Профили создаются триггером при регистрации. Пользователь может обновлять только поля онбординга; системная роль назначается сервером и не изменяется клиентом.
- RLS разрешает читать только собственный профиль; разрешение на обновление ограничено полями анкеты и проверкой `auth.uid()`.
- `src/proxy.ts` обновляет Supabase-сессию и перенаправляет неавторизованных пользователей с приватных маршрутов. Доступ к данным дополнительно защищается RLS и проверкой профиля на серверной странице.
- Google OAuth требует отдельной настройки провайдера и redirect URL в панели Supabase; email/password и magic link можно проверять без Google.
